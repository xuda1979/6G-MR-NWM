## 核心结论

1. **首要工程工作是把多时间尺度的数据组织好。** 建议用“采集端有界队列、带时间索引的历史环、不可变输入快照、持久化 Episode”组成数据链路；大帧按需使用内存池，控制事件使用消息队列。SPSC 适合单路采集到整理线程的传输，模型历史必须支持反复读取；双缓冲只适合满足所有权条件的最新整帧交接。模型已有年龄、周期和有效掩码接口；在线缓存、读写并发、时钟对齐和流式调度仍需开发。第 1 章逐项分析适用性、实现条件和阶段选择。
2. **总体架构由上层智能体、中层慢模型和下层快模型分工协作。** 智能体管理任务和模型；慢模型融合较长时间跨度的多源物理上下文；快模型根据状态和候选动作预测未来。目标权重和硬约束由人或上层策略明确配置，动作选择交由规划器及安全门。
3. **慢模型具有值得检验的价值，也应保留可移除的实现路径。** 它可能改善多模态上下文融合、跨窗口记忆和重复计算开销；现有真实数据实验尚未证明这些收益。下一步将与真正跳过慢层的轻量基线进行同条件比较。
4. **真实数据预测已有可复核结果，但尚不是语言模型慢层＋快层的实测结果。** UC6 与 UCC 5G 合计 215,444 条原始记录，各自使用独立轻量 LSTM 做三种子观测预测；没有在这两组数据上训练或评测完整语言模型慢层＋快层组合。UC6 的吞吐、RTT、RSRQ，以及 UCC 5G 的下行速率、RSRQ、SNR，其 NMSE 优于持久性基线；两组 RSRP 均较差，若干指标的 MAE 也变差。第 2.5 和 3 章具体区分实验路径、结果及限制。
5. **公开数据有局部动作监督，仍缺完整训练链路。** UC6/UCC 没有控制日志；2026-10-29 新增核查确认 DeepSense 有波束选择监督，Colosseum CSV 有资源/调度配置及反馈，但抽检配置恒定，不能据此宣称动作切换或完整规划器已训练。RF 仿真实验平台与实网测量分开计证；第 4 章与[动作数据核查](PLANNER_ACTIONS_AND_DATA_CN.md)说明范围。
6. **近期按“数据底座—预测基线—慢层增益验证—动作闭环”推进。** 首先补齐时间跨度与因果预处理，再验证三层架构的增量收益，最后接入有动作记录的仿真或隔离测试床。当前结果支持观测预测研究，尚不支持实网资源优化收益或控制时限结论。

## 1. 多时间尺度的数据结构与流式处理

本章是下一阶段实现的首要依据。下面的缓存、快照和持久化结构属于**建议设计**；现有模型数据接口与离线 LSTM 窗口结构见 1.9，不能把建议结构视为已经上线的系统。

详细字段契约、模型调用例子、载荷生命周期、容量预算、验收条件及 48 项常见问答，见独立文档[《MR-NWM 多时间尺度数据结构设计与问答》](MULTIRATE_DATA_STRUCTURE_DESIGN_CN.md)。本章保留面向进展汇报的选型与主要工程说明。

### 1.1 结构选型：哪些适合我们，为什么

**本项目适合组合使用多种结构。** 环形缓存适合持续更新的数值历史；图像、点云和 IQ 大块更适合“预分配载荷块＋引用”；控制指令和异常事件适合消息队列；配置需要版本表，训练轨迹需要持久化存储。以下是依据项目数据和调用方式作出的工程选型，不代表仓库已经实现，也不以某一种结构普遍优于其他结构为前提。

| 结构 | 本项目适用位置 | 为什么适合 | 条件、局限与当前取舍 |
|---|---|---|---|
| **SPSC 环形 FIFO** | 单个 CSI/IQ 采集器或单路遥测接收器，到唯一整理线程的接入通道 | 固定容量、预分配；读写只推进索引，不必搬移全部历史；并发关系简单 | 必须确实只有一个生产者和一个消费者；用于传输交接。当前 UC6/UCC 离线预测不依赖它，在线高速采集时优先评估 |
| **带时间索引的历史环** | 按实体/模态保存近期 CSI、KPI 和已提取的视觉特征 | 快慢模型需要不同长度、相互重叠的历史；容量有界，按时间反复取窗 | 读取不删除，写者管理保留边界；需处理乱序、覆盖和快照。它是本项目在线数据底座的主要结构，不能直接当作普通 SPSC 消费队列 |
| **双缓冲 / 三缓冲** | 只需最新一帧的相机、雷达或点云采集与编码交接；固定形状最新特征包 | 在完整帧写好后发布引用，避免读取尚未完成的帧 | 必须有读者占用/归还协议；两块都被占用时需要等待、丢新帧或增加块数。不能保留多帧训练历史；多读者或长时间占用时改用块池 |
| **有界消息队列** | Agent 的模型刷新请求、策略更新、告警、动作请求和执行确认 | 保留消息边界，便于校验 ID、截止时间、版本和处理状态 | 是否支持消息优先级取决于实现；关键消息应独立通道或明确定义调度。控制消息不能按传感器“保留最新”规则静默覆盖 |
| **字节流 Stream Buffer** | 后续接串口、RTOS 或某设备驱动的原始字节入口 | 适合尚未解析为观测记录的连续字节、ISR 到任务传输 | 需要另加长度/帧头、校验和解包；不自带实体、事件时间和窗口索引。当前 Python/张量主路径不需要专门引入 FreeRTOS 原语 |
| **预分配内存池** | 大体积 IQ 块、图像、点云和反复复用的输入/输出块 | 限制载荷总内存，减少热路径反复申请释放内存；队列只传描述符 | 它是存储分配机制，不是队列；需要块状态、引用寿命和耗尽策略。小型 KPI 初版用预分配数值数组即可 |
| **版本表＋持久化日志/文件** | 拓扑、配置、PolicyConfig、动作反馈和训练 Episode | 支持按生效时间查历史、跨消费者回放和训练审计 | 补足环形缓存的有限历史；磁盘/远端写入放在独立路径，不能假设永不积压 |

**首先区分两种“环”。** 接入 FIFO 的消费者取走记录后可以归还槽位；模型历史环在一次预测后仍保留记录，由历史时长和容量决定淘汰。例如，快模型读取最近 100 ms 的 CSI，慢模型读取最近 5 s 的 KPI，同一条记录可能被多个窗口和候选方案重复使用。若让快模型推进唯一 `tail` 并删掉历史，慢模型或记录器就可能再也读不到它。

环形结构是内存组织方式，不是存储芯片；数组在虚拟地址上连续，不等于必须物理连续。Linux `kfifo` 是可参考的内核 FIFO 实现，当前模型运行在用户态，不需要为采用环形结构而先编写内核模块。官方资料也区分了 FIFO 的满队列行为与内存顺序要求，详见 [S1](https://docs.kernel.org/core-api/circular-buffers.html)、[S2](https://www.kernel.org/doc/html/latest/core-api/kernel-api.html#kfifo-interface)。

建议的数据关系如下。数值流可以直接入接入队列；大帧队列携带块描述符。消息队列管理控制事件，不混入数值历史。

```mermaid
flowchart TD
    C["采集器与数据回放"] --> Q["数值或载荷描述符接入队列"]
    C --> M["图像与 IQ 载荷块池"]
    M -. "块引用" .-> Q
    Q --> I["校验、去重与乱序整理"]
    I --> H["分实体和模态的历史环"]
    H --> S["按 T/A 冻结输入快照"]
    V["配置与拓扑版本表"] --> S
    S --> F["慢层上下文与快层预测"]
    I --> L["独立记录队列与持久化 Episode"]
    S --> L
    E["控制消息队列"] --> D["调度、策略与执行管理"]
    D -->|"刷新请求"| S
    D --> L
```

CSI/IQ、图像、网络 KPI、拓扑和配置具有不同速率、体积和有效期。接入交接完成后，按以下四类逻辑存储组织：

| 结构 | 分区键或索引 | 保存内容 | 主要用途 |
|---|---|---|---|
| 近期观测历史环 | `(episode_id, entity_id, modality, stream_id)` | 有界时间范围内的观测值、时间和质量字段；每路独立容量 | 持续写入，快慢模型按时间反复取窗，读取不删除 |
| 配置与拓扑版本表 | 实体、配置类型、版本、生效区间 | 功率配置、邻区关系、拓扑、模型兼容信息等 | 查询某一时刻实际生效的版本，支持历史回放 |
| 不可变输入快照 | `snapshot_id` | 本次推理实际使用的数据、年龄、掩码、版本及窗口边界 | 固定一次推理的输入，隔离后台写入与候选方案比较 |
| 持久化 Episode 与原始数据存储 | 来源文件/数据块、实体、时间范围、哈希 | 原始数据、特征、快照引用、预测、动作与反馈 | 离线训练、故障追踪和实验复现 |

环形缓存只保存近期数据。需要保存的数据必须在槽位复用前复制给独立记录路径，或交接持有有效引用的载荷块，不能让异步记录器只记住一个即将被覆盖的槽位地址；保存确认与积压规则见 1.4。原始 IQ、视频、点云可写入分块文件或对象存储，历史环保存块引用、有效区间和必要特征，避免把每个 IQ 采样点作为一个复杂对象存储。拓扑和配置需要版本及生效区间，不能只保留一个“当前值”。

### 1.2 一条观测需要哪些字段

建议统一观测封装，数值载荷仍按模态定义。字符串类型、单位和维度等公共信息可登记在流描述表，热缓存仅保存短标识以降低开销。

| 字段组 | 建议字段 | 具体作用 |
|---|---|---|
| 身份与关联 | `episode_id / entity_id / cell_id / stream_id / modality` | 防止不同小区、设备和实验轨迹的数据混合 |
| 唯一性与顺序 | `sample_id / source_sequence / ingest_sequence / cache_sequence` | 去重、检测缺号，分别记录源端、接收端和乱序整理后的缓存提交顺序 |
| 时间 | `event_time_ns / arrival_time_ns / ready_time_ns` | 测量发生、到达接入端及派生特征就绪时刻；异步特征未就绪时不可当作已可用 |
| 统计区间 | `interval_start_ns / interval_end_ns` | KPI 或池化特征覆盖的时间范围；用区间结束时间确定其最早可用的物理时刻 |
| 时钟语义 | `clock_id / clock_mapping_version / time_uncertainty_ns` | 保留原始时钟与校正依据；不能将未校准的设备时间直接相减 |
| 采样与失效 | `period_ns / ttl_ns` 或配置中的等价字段 | 采样周期说明更新速度；TTL 是任务允许的最大观测年龄，两者独立 |
| 数值与质量 | `values / valid_mask / quality_flags` | 对每个字段保留缺失、异常、插补等信息；真实零值与缺失分开 |
| 数据定义 | `schema_version / unit_map / feature_version / normalization_version` | 防止单位、字段顺序和特征版本不兼容 |
| 大块载荷描述符（按需） | `pool_id / block_id / generation / byte_offset / byte_length / shape / dtype / device` | 引用 IQ/图像/点云块；代际号用于识别块复用，持有期另由引用/归还协议保证 |
| 来源 | `source_id / raw_ref / raw_hash` | 从特征追到原始文件或数据块；不强制每条样本重复计算大块哈希 |

时间建议用整数纳秒等固定单位存储，进入模型时再换算成秒。事件时间与到达时间应能映射到同一参考时钟；本地调度耗时可使用独立的单调时钟计量。对时误差超过任务容忍范围的流应单独处理或标记不可用于严格时间融合。

### 1.3 环形缓存的组织、索引与容量

#### 1.3.1 历史环保留窗口，接入环完成交接

建议每个分区采用预分配数组：`values[C,d]`、`event_time[C]`、`arrival_time[C]`、`valid[C,d]`、`sequence[C]` 和必要的版本/引用字段，其中 C 是容量，d 是该流的特征维度。高频数值字段分列存储，便于批量复制为张量。

历史环维护写入序号和最早仍可读序号。每次向主环提交时递增缓存序号 q，槽位可取 `q % C`。它与源端序号、到达时分配的接收序号分别记录，因为乱序整理会改变提交次序。槽位同时记录完整缓存序号；读取时核对序号，避免把绕回后新写入的数据误当成旧记录。不能只比较槽位下标，也不能把代际检查当成防止并发覆盖的完整协议。初版仍在短锁内复制记录。

经乱序整理后，主环的逻辑记录按事件时间有序，按时间范围查找；物理数组绕回时可视为两段，分别检索后拼成连续的输入副本。有序时间索引可支持区间检索，所以“环形结构绝不能随机查找”并不准确；复杂乱序排序、任意跨长历史查询则分别交给整理堆和持久化索引。数据时长超过容量时，要显式返回窗口不完整和覆盖计数。

#### 1.3.2 SPSC 无锁接入适用的前提

建议只在“一个采集/接收线程 → 一个整理线程”这一边界采用 SPSC。多个采集器可各有一条 SPSC，由整理线程汇入各历史分区；若多个生产者共用一条入口，就使用经过验证的 MPSC 队列或锁保护队列。快模型、慢模型、日志器共同读取同一块历史，不满足普通 SPSC 的并发模型。

在用户态 C/C++ 实现中，生产者完成载荷写入后，以 release 语义发布写入边界；消费者以 acquire 语义观察该边界，读完后再发布可回收边界，生产者确认可回收后才能复用槽位。应使用标准原子类型及经过核验的实现，不能把 `volatile` 或 Python GIL 当作跨线程/跨进程完整同步协议；特定宽度原子是否无锁也需在目标平台核对。Linux 的内核屏障 API 是内核语境，不能直接照搬成 Python 代码。[S1](https://docs.kernel.org/core-api/circular-buffers.html)

**满队列策略需要另外定义。** 常规非覆盖 SPSC 中，生产者管理写边界、消费者管理读边界；生产者不能为“保留最新”擅自推进消费者的 `tail`，否则可能覆盖正在读取的元素。接入端初版可拒收新记录并计数，或由消费者按约定跳过积压；真正覆盖式传输需要独立的所有权与并发证明。历史环则在短锁及快照复制协议下按保留范围淘汰。

`kfifo_put` 满时返回 0，`kfifo_in` 返回实际拷入数量；它们不等于“自动覆盖最旧数据”或“自动阻塞生产者”。调用者必须检查结果并实施所选策略。这也是本项目不直接采用“满了就覆盖”的原因。[S2](https://www.kernel.org/doc/html/latest/core-api/kernel-api.html#kfifo-interface)

#### 1.3.3 按历史、积压和载荷占用分别计算容量

容量由历史保留时长、峰值速率、允许乱序时长和突发量共同确定：

$$
C_m \ge \left\lceil r_m^{\mathrm{peak}}(W_m+L_m)\right\rceil+B_m.
$$

其中 W 为需要保留的历史，L 为乱序容忍，B 为突发余量。该式用于历史环与乱序区的联合记录预算；分开分配时分别核算，不把同一份余量重复算作可用容量。下面仅为设计演示，具体参数需要按真实数据量和目标硬件测量确定。

| 流 | 示例速率 | 历史 W | 乱序余量 L | 突发余量 B | 最小容量与示例分配 |
|---|---:|---:|---:|---:|---|
| CSI 特征 | 1,000 条/秒 | 0.10 秒 | 0.01 秒 | 20 条 | 至少 130 条，可分配 256 槽 |
| KPI | 10 条/秒 | 5 秒 | 0.5 秒 | 10 条 | 至少 65 条，可分配 128 槽 |
| 图像特征 | 20 条/秒 | 1 秒 | 0.1 秒 | 4 条 | 至少 26 条，可分配 32 槽 |
| 拓扑/配置 | 事件触发或低频 | 按业务回放需求 | 按配置生效语义 | 单独设置 | 使用版本表；近期引用可另设有界缓存 |

例如，每条 CSI 特征有 64 个 float32 值，数值占 256 字节；若固定元数据预算另为 64 字节，256 槽约占 80 KiB。这只是容量估算，未计字符串、索引、数据块、快照副本和分配器开销。原始高采样率 IQ 的内存预算必须按采样率、复数精度、天线数及保留时长另算。

接入 FIFO 还需按消费者最长允许停顿 D 另算 `C_ingress ≥ ceil(r_peak·D)+B`；历史环容量不能代替这一预算。若 CSI 峰值为 1,000 条/秒、整理线程允许停顿 20 ms、突发余量 20 条，入口至少需 40 个可用槽。采用留一个空槽区分满/空的实现时，物理槽数还要包含这个保留槽；容量为 2 的幂是可选实现优化，不是所有环的数学要求。

大帧块池按不同阶段**同时未归还的块的并集**计算：采集中、排队中、历史保留中、快照/编码中、记录中，再加突发余量；一块被多人引用只计一份载荷，不能把“队列深度”直接当作所需块数。零拷贝后读者占用越久，块池预算越大，相关规则见 1.5。

**历史保留期、历史输入范围和当前观测有效期分别管理。** 保留 100 ms 的 CSI 可服务历史建模和回放；若任务要求最新 CSI 年龄不超过 5 ms，还要单独检查最新观测条件。历史 token 可以有不同的允许年龄，但必须真实标注年龄和用途。当前编码器的 `max_age_seconds` 会屏蔽对应模态中过期 token；若统一设为 5 ms，就不能同时声称 100 ms 的 CSI 历史全部进入该路径。不能因为记录还在缓存中就认为可供当前控制使用。

### 1.4 写入、乱序、重复与背压

建议每个历史分区采用单写者。各采集任务通过独立 SPSC 或正确支持多生产者的有界队列接入，由同一整理任务校验、去重和提交；数值、帧引用与控制消息按 1.1 分流。消息结构需带类型与长度，不能把不定长字节流直接当作完整观测。FreeRTOS Stream Buffer 传字节，Message Buffer 保留变长消息边界，两者原生都以单写单读为前提；固定大小 Queue 是另一种原语，不能混为一种“自带优先级的固定消息队列”。[S3](https://docs.aws.amazon.com/freertos/latest/userguide/inter-task-coordination.html)

1. **校验后接收。** 检查实体、字段、单位、时钟映射和有限数值；为每个有效字段保留质量状态。未知版本不静默转成有效数据。
2. **短时乱序先整理。** 可用按事件时间排序的小顶堆，暂存允许乱序范围内的记录，再向时间有序缓存提交；相同时间戳允许有不同样本，去重应依赖来源与样本 ID。
3. **定义水位线与迟到策略。** 每流用最大已见事件时间减允许乱序量形成候选水位线，并结合心跳或流状态判断进度。水位线表示容忍假设，不能证明以后绝无迟到数据。早于主环已提交事件时间的迟到记录不直接追加到时间有序主环，而进入旁路日志或独立迟到索引；是否用于后续快照仍按事件时间、到达截止和 TTL 过滤。已冻结的快照不回写。
4. **按数据类型定义容量耗尽行为。** CSI/视觉流可按任务配置拒收、降采样或跳过积压，记录缺号与丢失；不无限阻塞采集。动作/确认/配置消息使用独立预算、请求 ID、截止时间与确认/重试规则，关键消息不按普通遥测静默覆盖；满时返回明确失败。策略版本在指定生效点切换，不能在一次候选比较中途改变。
5. **先记录，再发布。** 写入完整载荷和元数据后才发布序号/边界，使读取方不会取得半条记录。初版可使用短锁完成提交；无锁实现需另外验证内存可见性与覆盖行为。

**记录器是独立消费者。** 初版由整理/快照模块复制记录到有界记录队列，记录线程再写文件，并返回可追踪的提交状态；引用式大块交接则由记录器持有块，写完后归还。若任务要求完整保存，记录路径满时须在容量内保留未确认数据，必要时停止该次试验或拒收新数据；允许丢失的流要记录丢失区间。有限内存不能同时保证无限慢的记录器、无限运行和零丢失，不能靠“异步写盘”掩盖这个边界。

### 1.5 读取与快照：后台继续写，当前预测输入保持不变

在决策参考时刻 T 生成快照，同时冻结本次数据可用性的到达截止时刻 A。演示中取 A=T；真实部署需明确采集、决策与执行截止时间。候选输入至少满足：

$$
t^{\mathrm{event}} \le T,\qquad
t^{\mathrm{arrival}} \le A,\qquad
t^{\mathrm{ready}} \le A,\qquad
\mathrm{age}=T-t^{\mathrm{event}}\ge0.
$$

还需核对实体、版本、质量和任务配置的 TTL。统计量的事件时间使用统计区间结束时刻，其覆盖区间也必须截止于 T。上述就绪截止适用于直接使用已计算特征；若冻结当时已到达的原帧后再编码，要记录处理完成时间并计入决策截止预算，不能把编码时间省略。完整时间契约见独立设计文档第 4、6 章。

乱序整理与数据新鲜度需要共同考虑。若 CSI 允许年龄只有 5 ms，而水位线落后 10 ms，仅读取已提交主环会漏掉最新有效数据。建议提供两种快照策略：

- **优先新鲜度：**短锁内同时复制主环、待整理堆和允许使用的迟到索引，按本次 T/A 筛选、去重和排序。它使用当时已到达的数据，快照需标记时间窗口可能仍不完整。
- **优先时间完整性：**将输入截止限制在各必需流已确认的水位线，或仅在等待预算内等候；同时检查观测年龄。不能无限等待所有流，也不能通过等待获得已过期数据的有效性。

快照应记录采用的策略及各流进度。初版读取流程如下：

1. 由快照协调器捕获各流已提交的序号边界、待整理/迟到记录的可读集合和配置版本；按所选策略确定数据范围。初版串行冻结同一次输入，逐分区短锁复制，并保存各流实际边界；T/A 是一致的筛选条件，不代表所有传感器在同一瞬间采样。
2. 在短锁内选取并复制所需记录为推理私有副本；释放锁后再做较重的特征提取与张量编码。
3. 为快照登记 ID、T/A、各流来源序号、窗口边界、缺失率、观测年龄、预处理及归一化版本。
4. 从同一快照为多个候选动作建立独立预测状态和递归记忆。候选 A 的末态不能成为候选 B 的初态。
5. 直到本次预测完成，快照值和版本不变；后续新数据只影响下一次快照。

仅保存环形数组的内存视图不足以保证一致性：后台写入可能覆盖旧槽。后续若改为零拷贝，需增加数据块引用计数或固定页保留、代际校验和容量耗尽处理。初版优先采用可验证的复制快照，再依据实测瓶颈优化。

#### 1.5.1 双缓冲适合最新整帧交接，不承担历史保留

在只取最新相机帧的场景，可预分配 A/B 两块：采集器写空闲块，完整后发布为只读，编码器取得并占用它；编码完成后才归还。下一帧只能写另一块已空闲的缓冲，不能只因“指针已切走”就重写仍被编码器引用的旧块。读者长时间持有 A 时，B 写满以后也可能无空闲块；此时需明确丢新帧、有限等待，或使用三缓冲/更多块。三缓冲增加周转余量，仍不保证任意慢读者下永远不缺块。

对本项目的取舍是：**单消费者、只需最新整帧时可选双/三缓冲；多帧历史、多消费者或异步编码时选内存池＋描述符队列。** 例如视觉模型需要最近 1 s 的 20 帧图像时，两块帧存储不能替代这 20 帧的历史预算；若只保存逐帧提取后的特征，可以释放原帧，特征另入历史环。慢层生成的最新 `ContextPacket` 也可采用完整构造后发布新版本的方式，但旧推理仍持有旧包直到完成，不能强行复用其存储。

#### 1.5.2 大载荷用内存池，描述符和载荷寿命一起管理

建议按模态/尺寸预分配有限块池，块经历“空闲 → 写入中 → 已发布只读 → 全部持有者归还 → 空闲”的生命周期。例如，一个 IQ 块由接收器写入并发布，整理器、快照/特征提取器和记录器各按需持有引用；历史淘汰也要释放相应引用，最后一个持有者结束后块才能复用。FIFO 的描述符已出队，不代表载荷可以立刻回收。

同进程可用受管理的对象引用；跨进程共享内存应传 `pool_id / block_id / generation / offset / length` 等描述符或中间件句柄，不能直接传本进程裸指针。取得引用与回收必须有同步协议，避免“刚检查代际号，块就被回收”；超时不能作为覆盖仍被使用内存的理由。故障退出的持有者由明确的恢复流程处理。

例如后续接入 `640×480×3`、`uint8` 的未压缩图像，单帧约 0.88 MiB；同一帧交给两个读取者，用引用可共享一份载荷。但图像解码、特征提取、张量排布和主机到 NPU/GPU 的传输仍可能需要分配或复制，**描述符传输零拷贝不等于从设备到模型端到端零拷贝**。初版先复制小型特征；只有实测大载荷复制成为瓶颈时才优化。

iceoryx 的官方设计采用共享内存块、各订阅者队列和引用计数；ROS 2 的借用消息设计还要求底层支持和明确的归还责任。可借鉴这些所有权机制，但不能把所有 DDS、ROS 2 或 Zenoh 通道统称为同一种 SPSC ring，也不能从选择中间件直接推导本项目已经实现零拷贝。[S4](https://github.com/eclipse-iceoryx/iceoryx/wiki/Eclipse-iceoryx%E2%84%A2-in-1000-words)、[S5](https://github.com/ros2/design/blob/gh-pages/articles/zero_copy.md)

#### 1.5.3 快慢模型和记录器如何独立读取

近期版本由统一快照模块读历史环，快慢模型读取推理私有副本，记录器读独立队列。慢模型即使处理较久，也不会推进或占住快模型的唯一消费指针；新数据仍可写入历史环。该方案较易核验，但复制量和短锁时间都要测量。

将来确需共享历史时，可用多读者环形日志、独立读取序号或各读者描述符队列。若保留全部未读数据，最慢读者会决定可回收边界，必须设置容量与持有上限；若允许绕过落后读者，读取者必须检测覆盖、报告数据缺口并重新同步。仅增加几个 offset 不会自动解决载荷回收、过期和故障恢复。长期训练与审计仍从持久化 Episode 读取，不长期占用在线环。

### 1.6 不同速率数据如何进入同一次推理：具体例子

假设 T=A=10.000 s。下列数值、周期及 TTL 均为算法说明，不代表已验证的无线系统时限。

| 模态 | 示例内容 | 事件时间 | 到达时间 | 在 T 的年龄 | 存储与本次处理 |
|---|---|---:|---:|---:|---|
| CSI 特征 | 两路复信道拆成实部/虚部：`[0.80,0.05,0.60,-0.02]` | 9.999 s | 9.9996 s | 1 ms | 单路接入后入数值历史环；最新 CSI 若要求 TTL=5 ms，则有效 |
| 图像特征 | 外部视觉编码器得到的连续向量，原帧按需引用块池 | 9.970 s | 9.995 s | 30 ms | 特征入历史环；若 TTL=100 ms，则有效。编码尚未完成时不能把该特征当作已就绪输入 |
| KPI | 82 Mbps、18 ms、−10.5 dB、−88 dBm | 9.900 s | 9.920 s | 100 ms | 预分配小型数组历史环；若 TTL=500 ms，则有效 |
| 拓扑 | 邻区关系版本 v7 | 9.200 s | 9.250 s | 800 ms | 从版本表读取；核对生效区间，必要时再检查最大年龄 |
| 迟到 CSI | 另一条合法 CSI | 9.998 s | 10.004 s | 事件上已有 2 ms | 尚未到达，排除本次快照；后续到达按迟到规则接入 |
| 时钟异常数据 | 被标记为有效的未来事件 | 10.002 s | 9.999 s | −2 ms | 隔离并核查时钟，不作为有效观测 |

每个模态按自身需求取一个尾随历史窗口，保留若干原始特征或因果摘要，再转换为 `values[B,N_m,d_m]`。模型接收的年龄为 `age_seconds[B,N_m]`，并附采集周期及有效掩码。

高频数据可先按尾随区间做统计或特征压缩；降采样需考虑抗混叠。KPI 与拓扑保留自身速率及真实年龄，无需复制到每个 CSI 采样时刻。不同数据集、不同日期或不相关实体不能仅按行号拼成同步轨迹。

例如慢层每 100 ms 刷新、快层每 20 ms 发起一次新决策：10.000 s 时冻结快照，慢层生成调制包；10.020 s 时快层可取得更新后的状态/短窗，再由调度器判断旧调制包是否仍适用，必要时提前刷新慢层。此前快照、包和候选记忆保持独立，到 10.100 s 再生成常规新慢窗。这里描述的是待开发的外部调度方式，当前模型的单次多步 forward 见 2.4，不自带此定时运行能力。UC6/UCC 的秒级 KPI 不能通过环形缓存变成真实 20 ms 反馈。

**未来预测与实时刷新分别处理。** 在 T 生成快照后，模型可以一次计算未来多步的假设轨迹；若 10.020 s 要根据新测量重新作出真实动作决策，就必须由调度器重新检查观测与上下文是否仍有效。5 ms 的 CSI 有效条件不能由一个 100 ms 的缓存窗口自动保证。

### 1.7 模型输入、上下文缓存和长期记录各存什么

| 对象 | 核心内容 | 更新与隔离方式 |
|---|---|---|
| `ObservationSnapshot` | 各模态值、年龄、周期、掩码；状态、实体、来源和版本 | 每次决策冻结；原始观测与预测值分开标记 |
| `ContextPacket` | `gamma / beta / lora_a / lora_b`、环境上下文；建议附 ContextID、快照/模型版本和适用条件 | 慢层刷新时完整生成后发布；各推理持有其版本，最后使用者结束后回收；适用性检查由外部调度层落实 |
| `PolicyConfig` | 人设目标权重、硬约束、目标范围和 PolicyID | 策略变化时独立更新，避免把偏好当作物理测量 |
| `PredictionRecord` | 快照、模型/上下文版本、候选动作、预测时域及状态轨迹 | 每个候选独立记录；不写回“已观测”缓存 |
| `ActionFeedback` | 请求动作、实际生效动作、生效时间、执行状态和后续测量 | 执行确认后追加，用于残差、动作条件训练和回放 |
| Episode 存储 | 上述对象的关联、原始引用和校验值 | 追加写入并定期校验；训练划分按完整会话/轨迹等实体隔离 |

ContextID/PolicyID 生命周期和完整持久化链路是后续系统设计，当前模型只返回内部张量与摘要，不能宣称已有跨节点缓存协议。

### 1.8 正确性要求和首批验收用例

数据结构的价值要由可测行为验证。首批用例应覆盖：

- **环形绕回与并发：**多次覆盖后仍能返回正确时间范围；消费者读到的数据不被后台写入改动，不出现撕裂记录。
- **SPSC 边界与溢出：**队列满/空、连续绕回、生产者或消费者停顿、部分写入返回值有明确行为；禁止把多生产者场景未经同步塞入 SPSC；覆盖策略不能破坏读者正在访问的槽位。
- **大块所有权：**读者跨越多次帧发布仍读到原帧；最后引用归还前块不复用；旧代际描述符被拒绝；双缓冲无空闲块、池耗尽及消费者故障有可检查结果。
- **独立消费者：**慢模型或日志器滞后时，快模型按约定继续或回退；记录独立读者的积压、丢失和重同步，不能让一个消费者读走其他模型所需历史。
- **迟到与重复：**乱序输入、重复 ID、同时间不同样本、缺号和迟到超限都有确定结果及计数。
- **因果可见性：**未来事件或尚未到达的数据不进入当次快照；快照生成后新增数据不改变原决策。
- **缺失与过期：**按字段掩码，缺失不当作零值；TTL、版本或必需模态条件不满足时标记不可用并调用已配置回退。
- **版本与来源：**单位/维度/归一化版本不兼容时拒绝；跨小区或跨 Episode 数据不能误配。
- **资源边界与时限：**在预设峰值输入率下测量内存上限、队列水位、池占用和丢失率；分别统计入队/出队、快照、预处理/设备传输和端到端决策的 P50/P95/P99、观测最大值与截止违约率。声明负载和设备，观测最大值不当作已证明的最坏执行时间。
- **控制与保存保证：**动作消息不可被传感器淘汰策略覆盖；拒收、超时、重复请求及确认可追踪；要求完整保存的试验在记录队列耗尽时按既定规则停止或拒收，不静默漏写。
- **回放一致性：**同一快照、模型、动作、策略和评测配置能重现同一计算输入；随机推理需保存随机源。
- **在线预处理：**仅允许使用当时已到达的历史，比较离线插值与因果版本，记录由此产生的结果变化。

### 1.9 仓库已实现的数据结构与待开发项

| 项目 | 当前实现 | 下一步 |
|---|---|---|
| 模态观测 | `ModalityObservation`：`values / age_seconds / period_seconds / valid / adjacency / max_age_seconds` | 由采集层补齐源时间、到达时间、实体、版本及原始引用 |
| 多模态编码 | 数值投影、类型与时间嵌入、有效/过期掩码；可选拓扑消息传递 | 对接真实 RF 校准、视觉/点云编码与历史选取 |
| 慢层输入 | `FoundationInputs`：目标文本、模态字典、可选已核实外生事实文本 | 从冻结快照构造输入；为来源和时钟建立可追溯映射 |
| 离线 LSTM 窗口 | `UC6Windows / UCC5GWindows`：历史、未来、上下文、观测掩码、会话/片段 ID、划分及归一化统计 | 保留既有实验协议，新增严格物理时间与因果预处理版本 |
| 多窗口预测 | `rollout` 推进固定观测快照的年龄，传递预测末态与摘要 | 在线流由外部逐窗口重新传入；还需实现数据采集、缓存和调度 |
| 环形缓存与流式运行 | 尚无完整实现 | 先实现历史环、正确并发的有界接入、复制快照与回放；高速入口再评估原生 SPSC，大载荷再评估块池 |

当前 `TypedModalityEncoder` 将 `log(1+age)` 和 `log(1+period)` 编码进特征；`max_age_seconds` 配置后会屏蔽过期 token。模型不会自动维护时间索引、等待新数据、缩减超长输入或在每个快步重新检查 TTL。模型中的 `resampler` 压缩快层隐藏特征，原始传感器重采样另由数据管线承担。

源缓存需要保存字段级缺失信息，但当前 `ModalityObservation.valid` 是 `[B,N]` 的 token 级掩码，`period_seconds` 也是模态对象级标量。部分字段缺失和变采样间隔需要明确适配或扩展后训练，不能直接宣称已经无损接入；具体选择见独立设计文档 9.1。

### 1.10 当前先做什么，哪些实时系统技术后续再用

| 阶段/技术 | 本项目选择及原因 | 引入条件与验证 |
|---|---|---|
| **当前 UC6/UCC 与原型** | 保持离线分组窗口；用 NumPy/张量预分配数组、短锁、正确的有界接入和复制快照实现回放原型。KPI 小、速率低，优先保证时间与缺失语义 | 检验同一因果记录在回放和在线适配中的输入一致性；先测量再决定是否需要原生队列 |
| **后续高速 CSI/IQ 接入** | 若采集和整理边界确实单写单读，采用经过验证的 C/C++ SPSC；IQ 按块交接，不逐采样点分配 Python 对象 | 单独测峰值率、CPU 占用、溢出与调度抖动；跨线程/进程及目标架构内存顺序必须正确 |
| **后续多模态大帧** | 先选择“只取最新帧”或“保留多帧历史”的任务语义，再选双/三缓冲或有限块池；特征与原帧分别预算 | 验证编码器/模型持有期、并行读者、池耗尽、回收与实际复制量；不能仅以帧类型决定一定用双缓冲 |
| **共享内存 / iceoryx / ROS 2 / Zenoh** | 多进程大块重复复制确为瓶颈时再评估；当前独立 LSTM 不因引入中间件而自动受益 | 按所用实现、版本和配置验证借用、布局、回收、QoS 和故障恢复；不把共享内存等同于端到端零拷贝 |
| **CMA 与 DMA** | 普通用户态历史环不要求 CMA。只有实际驱动/设备的 DMA 地址、映射和一致性要求需要时才使用相应驱动分配机制 | CPU 虚拟地址、物理地址与设备 DMA 地址是不同概念；按设备与 DMA API 核验，不能从“数组连续”推导“必须物理连续” [S6](https://docs.kernel.org/core-api/dma-api-howto.html) |
| **PREEMPT_RT、绑核、内存锁定** | 确有目标时限和设备后，再评估实时调度、CPU/IRQ 亲和性、预分配/预触页与 `mlock`；推理、持久化和采集线程按职责隔离 | PREEMPT_RT 使更多路径可抢占；不能把长时间屏蔽抢占当作通用优化，也不能由换内核直接保证微秒级抖动 [S7](https://docs.kernel.org/core-api/real-time/differences.html) |

“几十纳秒”可能是特定硬件、缓存命中、特定载荷下的一次队列操作测量，不能作为本项目端到端延迟承诺。数据到模型还要经过唤醒/调度、乱序等待、快照、特征编码、设备传输和推理；应按 1.8 分段实测并统计截止违约。当前 20 ms/100 ms 示例仍是设计时域，不是已经满足的控制性能。

因此，本阶段的具体交付是**带时间索引的历史环＋不可变复制快照＋独立记录/控制通道**，同时预留接入 FIFO 和大块描述符接口。SPSC、双缓冲、共享内存与实时 Linux 按实际采集形态和瓶颈逐步引入，既支持轻量单模型，也支持后续慢快模型。

## 2. 上层智能体、中层慢模型、下层快模型的架构与价值

### 2.1 三层职责和外部执行链路

```mermaid
flowchart TD
    A["上层智能体：任务、模型管理、更新请求"] --> P["外部策略与规划器：人设目标、约束、候选动作"]
    D["多时间尺度输入快照"] --> S["中层慢模型：多模态物理上下文"]
    D --> F["下层快模型：候选动作条件预测"]
    S -->|"缓存调制参数"| F
    P -->|"候选动作"| F
    F -->|"状态轨迹"| E["外部评估与安全门"]
    P -->|"评分规则与硬约束"| E
    E --> X["受控执行、实际状态反馈与记录"]
    X -. "下次观测与残差" .-> D
```

| 层次 | 输入例子 | 输出例子 | 更新/调用边界 |
|---|---|---|---|
| 上层智能体 | “优先保障业务时延”；人设权重与约束；模型能力、网络告警、执行反馈 | 结构化任务、PolicyID、工具调用、模型选择和刷新/重规划请求 | 任务变化、异常或监督周期触发；完整 Harness 仍待实现 |
| 中层慢模型 | 冻结快照、当前状态、环境、上窗摘要和已核实外生事实 | 物理上下文与快层调制包；语义路径当前还输出目标权重 | 每个宏窗口或后续事件刷新；现有代码包含慢层路径 |
| 下层快模型 | 当前/上一预测状态、该步候选动作、缓存上下文和窗口内递归记忆 | 下一状态及隐藏特征；K 步组成状态轨迹和摘要 | 单次调用内部递推 K 步；预测输出不直接构成动作优化 |
| 外部规划/安全/执行 | 候选轨迹、人设策略、明确约束、接口状态 | 选中的动作、拒绝原因、实际生效值及反馈 | 有限候选评分已有合成参考；完整实网执行仍待接入 |

参考任务默认六维状态为两路信道增益、两路队列和两路干扰；动作是两路归一化功率，K=5。吞吐、时延等新输出需要相应任务定义或评价计算；不能把当前六维预测直接描述为已有的真实 5G KPI 输出头。

### 2.2 中层慢模型具体做什么

语言基座路径 `LanguageBasedWorldModel` 对同一个预训练语言 Transformer 执行两次前向：

- **物理视图：**接收状态、环境、上窗摘要、多模态 token 及已核实外生事实，形成物理上下文，不接收目标偏好文字。
- **语义视图：**在公共输入后追加目标偏好文本，供目标头处理。目标改变可影响候选评分；固定物理条件和候选动作时，物理预测应保持不变。

物理上下文经过调制头输出 `gamma / beta` 和低秩因子 `lora_a / lora_b`，供快层在一个窗口内复用。默认宽度 32、低秩 2 时，批量 B 下两组向量形状均为 `[B,32]`，两组低秩因子均为 `[B,32,2]`。它们是本次输入生成的运行时条件。共享参数选项只关联慢层外围物理专家与快层物理核心，未把语言 Transformer 内部整体改成快模型；当前两次语言前向也没有共享前缀 KV 缓存。

需要区分三类“权重”：

| 类型 | 谁决定/生成 | 何时更新 |
|---|---|---|
| 吞吐、时延、能耗等目标权重 | 人或上层策略明确设定；自然语言解析只能提供可核验的结构化建议 | 业务策略变化时 |
| 神经网络训练参数 | 根据训练目标和数据进行学习 | 离线训练或受控再训练/微调时 |
| `gamma / beta` 与动态低秩因子 | 慢模型由物理输入生成 | 慢层上下文刷新时 |

当前代码仍有学习式 `objective_weights` 输出头。本报告建议增加显式人设策略输入及固定策略路径；该接口尚未在本次文档更新中修改。无论采用何种解析方式，硬约束始终由外部确定性检查落实。

### 2.3 慢模型的价值、成本及保留条件

| 价值假设 | 具体作用 | 当前证据与后续验证 |
|---|---|---|
| 融合多模态和不同年龄的观测 | 将 CSI、拓扑、移动/环境等信息综合成紧凑条件，减少快模型直接处理长输入的负担 | 年龄/掩码与适配接口已有代码；真实无线任务上的收益待训练验证 |
| 表达跨窗口环境变化 | 将上窗隐藏摘要和新的观测结合，帮助描述较长依赖或外生变化 | 末态与摘要反馈已实现；需与只输入短历史的小模型比较 |
| 复用较昂贵的上下文计算 | 一个慢层结果支持 K 步快预测或同一快照下多个兼容候选 | 结构上可复用；需测量预处理、双语言前向、候选数量与快层的总成本 |
| 利用预训练表征 | 尝试迁移多模态/语义理解能力，降低不同场景的适配难度 | 已有语言基座接入检查；没有建立其无线任务普遍优于轻量模型的结论 |

一个窗口的计算成本约为 `C_预处理 + C_慢层 + K·C_快层`。复用可减少“每一步重新调用完整慢层”的成本；与完全省去慢层的小模型比较时，仍要支付慢层开销。不能仅根据大小模型分工就声称系统一定更快或更准确。

因此保留两条可比较路线：**轻量预测器直接工作**，以及**慢层上下文加快预测器**。当数据维度较低、任务单一、历史较短时，先采用轻量路径；当跨模态、跨场景、较长依赖的优势经实验证明且成本可接受时，再保留慢层。智能体的任务管理功能可独立配置。

现有 `modulation=False` 消融仅关闭调制效果，仍会计算慢层；后续需要单独实现真正跳过慢层的基线，才能比较完整开销和增量收益。

### 2.4 慢快模型如何调用、如何刷新

以 K=5、预测步长 20 ms、宏窗口 100 ms 为说明。**这些是调用者设定的物理时间标签，未经过目标无线设备验证；当前代码在一次 forward 内立即循环计算五步，不会自动每隔 20 ms 调用一次。**

| 阶段 | 数据/调用 | 发生的更新 |
|---|---|---|
| T=10.000 s 构造输入 | 从 1.6 的缓存生成固定快照，准备初态、环境和五步候选功率 | 新建 `FoundationInputs`；保存输入来源及策略版本 |
| 慢层调用 | `forward_slow_tier(inputs, state, context, previous_summary)` | 生成本窗口调制包；语言基座路径内部有物理/语义两次前向 |
| 快层第 1 步 | `forward_fast_tier_step(state, action_1, packet, memory=None)` | 预测 T+20 ms 状态，建立递归记忆 |
| 快层第 2–5 步 | 每步用上一步预测状态、新候选动作、同一 packet 和当前记忆 | 得到 T+40、60、80、100 ms 的假设状态 |
| 窗口结束 | 压缩五步隐藏特征形成 `sync_summary` | 返回 `pred_states[B,5,6]` 与摘要；此时未自动执行任何动作 |
| T=10.100 s 新决策 | 外部调度装入新观测、重算年龄/掩码、检查版本并调用下一窗口 | 在线可用真实状态估计修正初态；自由滚动评测则延续预测末态；传入上一摘要 |

常规 `model(inputs, state, actions, context, previous_summary)` 已在内部串起一次慢层与 K 次快层。每次 forward 的快层递归记忆重新开始，跨窗口传递的是状态与压缩摘要；完整快层记忆不会自动跨窗延续。

现有 `rollout` 处理固定观测快照，通过 `advance` 增加年龄，不会从缓存读入未来新测量。流式更新必须由外部逐窗口重建输入。运行时刷新上下文与模型参数训练分别进行，推理调用不等于在线学习；当前 TTL 检查在慢层编码时发生，快步中的实时过期与回退仍需调度层实现。

### 2.5 三层架构的当前成熟度

目前有三类不同的证据，不能将一种实验的结果转移到另一种模型或数据上：

| 证据类别 | 使用的模型与数据 | 已得到什么 | 还不能说明什么 |
|---|---|---|---|
| **真实测量的 KPI 预测** | UC6 和 UCC 5G 各自训练独立 `KPIForecaster` LSTM；每组有 3 个种子结果 | 在分组测试窗口上，与持久性基线比较吞吐、时延或信号类 KPI 的预测误差，完整数值见第 3 章 | 这两项实验没有调用 `LanguageBasedWorldModel` 或其快层，不能说明语言慢层、慢快调制或智能体的收益 |
| **轻量慢快模型的合成对照** | 不含预训练语言基座的轻量参考模型；双链路归一化合成任务 | 有慢快结构、共享/不共享等设置与数值模型基线的对照 | 合成模型分数和计时不能作为真实网络或语言基座的性能结论 |
| **预训练语言基座的集成检查** | Qwen2.5-0.5B 冻结语言骨干；合成状态/动作和随机生成的 CSI、IQ、拓扑输入 | 核验语言骨干与慢快前向连接、数值适配器梯度及该检查条件下的偏好隔离，输出形状为 `[1,5,6]` | 数值适配器和预测头未进行无线任务训练；没有 UC6/UCC 准确率、慢层增益或实网时延结果 |

第三类记录见[预训练语言模型集成结果](../results/pretrained_integration.json)及[对应检查脚本](../scripts/pretrained_demo.py)。该检查包含一次梯度反向检查，不代表已经对无线任务完成模型训练。语言基座路径的多模态接口、两种视图、慢到快调制和跨窗反馈是**代码能力**；其真实网络预测效果与增量价值仍需单独实验。上层 Agent Harness、在线缓存/调度、ContextID 生命周期、完整安全执行与真实动作闭环仍待开发。

UC6/UCC 5G 的 LSTM 接收 KPI 和移动上下文，属于真实观测预测基线；这不等同于用同场景 CSI、IQ、图像等输入验证语言慢层的多模态融合。两组数据都缺少功率、PRB、波束等实际控制动作日志，当前不能据其结果判断候选无线动作的因果效果。

## 3. UC6、UCC 5G 的 LSTM 预测实验与详细结果

### 3.0 本章结果究竟由哪个模型产生

**UC6 和 UCC 5G 的下述结果来自两组分别训练的独立 LSTM，均不是语言模型慢层＋快层组合的测试成绩。** 两个训练脚本各自定义并调用 `KPIForecaster`：将 8 个历史记录点的 4 项 KPI 和 5 维移动上下文输入模型，直接输出未来 4 个记录点的 4 项 KPI；两组数据分别训练，种子均为 11、22、33。LSTM 读取历史序列后由线性头一次输出四步，不能把它说成第 2 章中按候选动作逐步递推的快层。

每个数据集以同一测试窗口上的**持久性预测**作参照：将处理后历史窗口的最后一个值重复到未来四个点。以下是代表性结果，LSTM 为三种子均值，误差越小越好；全部指标和样本标准差见 3.4—3.6。

| 数据集与指标 | NMSE：持久性 → LSTM | MAE：持久性 → LSTM | 如何理解 |
|---|---:|---:|---|
| UC6 吞吐量 | 0.183949 → 0.114244 | 8.41 → 7.35 Mbps | 两种误差均改善 |
| UC6 RSRP | 0.001060 → 0.001576 | 2.40 → 3.38 dB | 两种误差均变差 |
| UCC 5G 下行速率 | 0.485276 → 0.432061 | 29,328.44 → 32,198.30 kbps | NMSE 改善，但 MAE 变差 |
| UCC 5G RSRP | 0.000841 → 0.004214 | 1.34 → 3.75 dB | 两种误差均变差 |

这里的 NMSE 按目标原始数值能量归一化，未减去均值，尤其不能单凭 RSRP 的小数值判断实际误差；MAE 是同一测试协议下的绝对误差。UC6/UCC 的数据名义上为秒级，当前代码按**记录行**而非严格物理秒数切窗，不能直接将“8 点→4 点”解释为固定的 8 秒→4 秒。现有插值还可能使用未来观测，因此这些结果不是严格在线因果评估。

对语言模型慢层＋快层组合，目前没有对应这两组真实数据的模型训练、同条件 LSTM 对照、逐指标误差或端到端时延记录；不能从表中得出“慢层提高了多少”或“组合适合毫秒级控制”的结论。两组数据缺少实际动作日志，但仍可用于后续**无动作观测预测**对照；动作条件效果需要有动作及反馈的数据另行验证。

### 3.3 指标定义与重算口径

以下均为现存逐种子 JSON 记录的重算；未新跑模型。MAE/RMSE/NMSE 越低越好。误差在反归一化之后计算，未来四步及有效测试窗口合并计分：

$$
\mathrm{MAE}=\frac{1}{N}\sum_i|\hat y_i-y_i|,\quad
\mathrm{RMSE}=\sqrt{\frac{1}{N}\sum_i(\hat y_i-y_i)^2},\quad
\mathrm{NMSE}=\frac{\sum_i(\hat y_i-y_i)^2}{\sum_i y_i^2}.
$$

这里 NMSE 的分母是目标的原始数值能量，未减去均值，不能解释为按目标波动方差归一化；RSRP 等带较大直流偏移的目标尤其应结合绝对误差阅读。改善率取 `100×(1−LSTM均值/基线)`，正值表示误差降低，负值表示变差。

“±”表示三次记录的样本标准差，基线在三种子间相同。UC6 的种子 22 与另两次记录使用不同 Python/PyTorch/NumPy 版本，因此其波动还包含环境差异，不能全部归因于初始化，更不能作为部署置信区间。以下汇总也没有分预测步长、分场景或分尾部给出结论。

**结果解读：**

### 3.7 当前结果能支持什么、还缺什么

现有结果证明已记录一条可在两类真实测量上运行的“读取—分段—窗口—LSTM—基线评分”流程，并暴露了按指标评估与强基线比较的重要性。它们尚未证明语言基座、慢快调制、多模态同步融合或真实动作优化有效。

后续复现仍需补齐：

1. 逐窗口/逐步预测、目标及掩码，按真实物理时间计算的预测跨度分布和错误分位数。
2. LSTM checkpoint、完整解析配置、运行代码哈希、数据/划分清单、驱动及加速器依赖版本；现有入库结果 JSON 不足以完整回放训练和评分。
3. 统一环境下的重跑与更强基线，包括逐目标持久性、线性/自回归及适用的轻量时序模型；统一预算比较。
4. 严格因果的数据处理、缺失/过期与跨会话泛化评测；在有动作数据后另行评价控制收益。

### 3.8 怎样在真实数据上验证慢快组合

**第一步先验证观测预测中的慢层增量。** 在 UC6/UCC 分别保留完整轨迹/会话划分，统一可见历史、目标、掩码、预处理和预测时域，重跑持久性、独立 LSTM、真正跳过慢层的轻量预测器，并与适配后的“小型慢上下文＋快预测器”和“预训练语言慢层＋快预测器”比较。先建立严格因果版本，同时保留当前结果作历史记录；所有模型在同一新协议下重新评分，不能直接把新旧协议的数字拼成对照。

这两组数据没有实际动作：需要新增**无动作观测预测的任务头或适配路径**，让各模型预测同样的四项 KPI 和未来四个记录点；不能把未知动作写成零功率并宣称得到动作条件结果。现有参考慢快模型默认是六维双链路状态、两维功率动作和 `K=5`，与这里的四 KPI、无动作、四个未来点不直接匹配，必须先修改任务接口并训练，不能直接套用默认输出。UC6/UCC 不包含同场景的完整 CSI/IQ 与视觉数据，因此这个阶段主要检验慢层对**已有数值观测与移动上下文**的价值，不代表完整多模态融合已验证。

**第二步再验证动作与多模态能力。** 选择具有原生配对模态的数据单独做融合任务；在可控仿真或隔离测试床采集“观测—实际生效动作—后续反馈”的同步轨迹，训练和比较动作条件预测，再与规则/优化基线评估候选动作排序及闭环效果。仿真、人工注入延迟和真实采集分别标记。

正式比较需预先固定训练/验证/测试划分、种子、预测目标及主指标，分别报告各步 MAE/RMSE/NMSE、误差分位数、缺失和跨会话表现；记录参数量、训练预算、设备、模型加载、预处理、慢快前向和端到端时延。既报告精度，也报告慢层增加的成本；只有在同条件下表现稳定改善且满足事先约定的误差与时延要求时，才能认为慢层带来了实际增量。

| **独立测量的业务后果** | UC6 有端到端 RTT，UCC 的 PING 大量缺失；两者未建立本项目所需的 RAN 排队时延、尾部 QoS 与能耗标签链路 | 无法据现有目标直接训练/验证所有吞吐—时延—能耗评价，不能把 RTT 等同于 RAN 队列时延 | 按已有真实标签定义任务；补业务反馈和能耗测量；目标权重由人配置，无需等待数据集提供偏好权重标签 |
| **足够的独立场景与动作覆盖** | 原始行与滑动窗口高度相关；现有实验只有两组数据，未形成多运营商、多小区、故障、突变等场景的分层覆盖证据 | 限制跨场景泛化、异常恢复及安全回退结论；样本多不代表动作和环境覆盖充分 | 建立场景清单和按会话/设备等隔离的评估；分开报告未覆盖、正常与受控扰动场景 |
| **数据版本、许可和获取信息的一致性** | 候选的下载/许可确认程度不同，部分有非商业限制或授权待复核；6 项候选尚未用于本仓库训练 | 限制合法可用的训练集合和可重复获取，增加任务适配工作 | 固定具体版本、条款和来源；先接入权限明确且任务匹配的子集，不将候选清单计为已训练数据 |

动作记录是重要前提，但仅有动作列也不能自动证明因果效应：还需记录行为策略、可选动作范围与外生条件，检查动作覆盖和混杂；必要时采用受控实验设计。缺失动作不能填零后当作真实“零功率动作”。

### 4.2 八项候选分别适合补什么、还缺什么

| 数据源 | 可利用的信息 | 对完整 MR-NWM 的主要不足/待核验点 |
|---|---|---|
| DeepSense 6G | 部分场景的波束功率、相机、GPS、雷达、LiDAR 配对信息 | 模态组合因场景而异；最优波束标签不等于实际施加的波束动作；缺少本项目所需完整队列/资源/动作反馈链路，尚未接入训练 |
| DICHASUS | 实测 CSI 与位置；可做信道表征、定位，连续片段可评估时序预测 | 需区分空间扫描与自然运动时序；未确认本项目的调度、队列和干预动作；尚未接入 |
| UCC 5G | 商用网终端 KPI、位置与移动信息；已有观测预测基线 | 无动作日志；PING 缺失严重；秒级记录无法直接监督毫秒级快层；不包含同场景的完整多模态传感器流 |
| Lumos5G | 商用毫米波吞吐与用户上下文候选 | 尚未完成全包接入与许可复核；未确认完整动作干预和网络内部状态 |
| 5G-IANA UC6 | 吞吐、端到端 RTT、信号质量与位置；已有基线 | 无动作日志；重复时间戳、信号指标缺失和轨迹异常需处理；RTT 与 RAN 排队时延含义不同 |
| 5G-IANA Nokia 路测 | 位置、上下行吞吐、PING | 199 个独立轨迹点，三份 KML 内容重复，仅样式不同；规模小、间隔不均匀，适合加载/缺失处理验证 |
| Telecom Italia Milan | 10 分钟粒度业务活动与空间信息 | 活动强度不等于吞吐、PRB 或能耗；网格不等于基站拓扑；与其他地点的快尺度数据没有天然同步关系 |
| WiSig | 真实 WiFi IQ 与设备/接收机/日期标签 | 主要支持射频表征/指纹任务；包与日期不能视为连续蜂窝控制轨迹，接收机间同步及任务迁移需另验 |

**仍可推进的训练与受阻范围需要区分。** 两组 KPI 的轻量预测可以继续改进；CSI/IQ 表征和配对多模态波束任务可以逐一接入。完整慢快模型的联合训练、跨时间尺度物理状态演进，以及动作优化效果验证，需要更符合目标场景的数据包。

此外，当前插值可能使用未来观测、按行号切窗、历史掩码未作为 LSTM 输入、环境与实验清单不完整等问题，属于**本仓库的数据管线和实验记录缺口**，应优先自行修复。RSRP 和部分 MAE 退化仍需排查模型、损失、预处理与分布因素，不能全部归因于公开数据不足。

### 4.3 首个动作闭环所需的最小数据包

保留“两个或少量小区的功率与干扰协调”作合成参考；结合第 4.4 节新增数据核查，首个新增网络动作任务优先审查“切片预算＋调度模式”。分别规定必需字段及可选字段，每个 Episode 至少关联：

1. **运行头信息：**拓扑/实体、模型及预处理版本、频段与单位、时钟映射、行为策略及允许动作范围。
2. **每步可见观测：**事件时间、到达时间、必要信道/干扰状态、实际功率、负载或队列及质量/缺失信息；字段由动作预测所需的可观测性决定。
3. **请求与实际动作：**候选/请求动作、实际生效值、生效时刻、成功/拒绝/超时状态，防止用未执行请求替代真实动作。
4. **后续独立反馈：**与动作时间对应的吞吐、队列/时延、干扰；只有纳入能耗目标时才必须增加可核验的能耗测量。
5. **轨迹和覆盖信息：**会话/实验组、移动和业务变化、异常事件、可用动作覆盖，以及训练/验证/测试归属。

先用可控仿真生成此结构、检验代码和评估协议，再在隔离实验网获取小规模真实同步轨迹。模拟、人工注入延迟和实测字段分别标记；不把仿真或派生标签写成真实设备测量。

### 4.4 公开动作数据与规划范围补充（2026-10-29）

**规划器与世界模型需要分别定义。** 世界模型预测候选动作后果；规划器在约束内比较这些后果、选择动作或序列，可以先用枚举/采样/MPC 实现，无需先训练 actor。策略网络可在搜索过慢时另行蒸馏。当前代码只有两链路有限功率候选的单步评分，没有一般序列规划、actor 或实网动作闭环。

论文现已定义六类动作：功率/干扰、资源预算/调度、波束、移动性/关联、准入/节能、测量/上报。仅功率行对应当前合成审计；其余为有界扩展方案。上层选择预算/模式与本地逐时隙执行分工，不能同时争夺同一执行器；吞吐/时延是结果，刷新上下文是上层操作，不应混作无线动作。

公开数据并非全部没有动作相关监督：DeepSense 可用测得波束功率及最优索引训练选择；Colosseum COMMAG/ColO-RAN 的两份实际抽检 UE CSV 含资源/调度/功率系数与队列、CQI、吞吐，但三项配置在各文件内均不变，不能据此训练动作切换瞬态，功率系数恒为 1 也不构成功率变化覆盖。COMMAG README 虽描述动态调整，仍需用实际日志核验。Commercial Traffic Twinning 官方说明提供不同资源/调度配置和跨层反馈，本次尚未下载完整归档。

Colosseum/Twinning 属于 RF 仿真实验平台证据；业务回放源于商用网不等于动作后果也在商用实网测得。优先利用这些受限监督，缺少多步动作覆盖时再补可控仿真，保存实际动作与生效时间，最后以独立受控实测验收。上述数据均未计入本项目新训练成绩。固定版本、抽检哈希、动作表和训练步骤见[详细核查](PLANNER_ACTIONS_AND_DATA_CN.md)。

### 4.5 对开发顺序的影响

优先解决可自行推进的时间与因果预处理，保留已经能做的 KPI 预测；并行选择一个具有原生多模态配对的数据场景。随后取得具备状态、已施加动作及反馈的数据，验证动作条件快模型，再判断慢层融合是否提供增益。完整动作日志和配对多模态的缺口主要限制后两步，不应成为停止所有训练工作的理由。


## 5. 下一步开发计划

按阶段验收推进，后续阶段依赖前一阶段证据；以下为开发计划，不是已完成结果或固定时间承诺。

| 优先级/阶段 | 主要工作与交付物 | 验收条件 | 依赖 |
|---|---|---|---|
| **P0：统一时间与实验口径** | 冻结数据版本和会话划分；统计重复/乱序时间戳、间隔与窗口跨度；完整保存配置、代码/数据哈希、checkpoint 和逐点预测；新增因果预处理协议 | 每个窗口可追到原始记录及物理跨度；训练/测试组隔离可自动检查；相同记录能独立复算全部表格；旧结果保留且不与新协议混用 | 当前记录和原始数据权限 |
| **P1：实现多时间尺度数据底座** | 按 1 章实现统一观测封装、有界接入与分区历史环、乱序整理、版本表、复制快照和独立记录/控制通道；建立 `ObservationSnapshot → FoundationInputs` 适配；按 1.10 的条件评估 SPSC 和大帧块池 | 1.8 的正确性用例通过；内存有界，读者独立，丢失/迟到/覆盖可见；在约定负载下记录各阶段延迟分位数、截止违约率与吞吐 | P0 的时钟与字段定义 |
| **P2：改进真实数据轻量基线** | 在 UC6/UCC 上统一运行环境；先保持目标和划分，对比因果处理、掩码/年龄输入、残差预测、MAE/Huber 等损失；对 RSRP 单独保留持久性回退 | 固定主指标及 MAE/尾部等保护指标；按 1–4 个未来点及物理时间分别报告；性能变差的目标明确拒绝升级；验证集选择，测试集作最终评估 | P0；P1 支持流式验证 |
| **P3：验证慢模型的增量价值** | 增加真正无慢层路径；比较轻量单模型、小型慢上下文+快模型、预训练慢层+快模型；先训练适配器/任务头，再评估是否微调骨干；补人设 PolicyConfig 接口 | 可见观测、划分、时域和候选相同，记录参数/训练及推理预算；报告跨场景/缺失/过期表现与端到端时延。只有增益稳定且成本符合预先约定预算时保留慢层 | P1/P2 和适用的多模态配对数据 |
| **P4：建立智能体与动作仿真闭环** | 先定义有界工具和任务配置，再接规划器、安全门、ContextID/PolicyID、更新/失效/回退及动作确认；生成观测—已施加动作—后续状态的同步 Episode | 各候选隔离；固定动作下目标改变不污染物理预测；过期/超域/失败触发确定行为；对比规则控制和适用优化基线，分别报告控制收益与计算成本 | P1–P3 的可用组件及可控仿真 |
| **P5：扩展数据与隔离测试床** | 按许可和任务选择 DeepSense、CSI/IQ 等候选数据，先完成特征与时间映射；闭环通过后接真实遥测，逐步从只读/建议模式进入有界动作试验 | 模态、实体和物理时间可对应；无动作数据只报告预测/表征；目标硬件完成采集到执行的完整时延、故障恢复和回放核验后再决定扩大试验 | 有效的数据/设备接口与前序验收 |

### 5.1 最先应形成的可交付版本

近期最小可交付版本由三部分组成：

1. **能连续写、稳定读、可回放的数据缓存与快照模块。** 先通过 UC6/UCC 离线回放模拟异步到达、延迟、乱序和缺失；人为注入的到达时间或延迟必须标为受控实验条件。
2. **一份统一环境和因果数据协议下的 LSTM/强基线报告。** 完整保存模型及逐点结果，重点解决 RSRP 和 MAE 退化，不先扩大模型规模。
3. **一套慢层可插拔的评估接口。** 在真正无慢层的基线上量化慢层增益与额外开销；智能体只管理已声明能力的模型与工具。

### 5.2 资源与协作需求

- 数据工程需要确认各源的时钟、单位、实体、版本、实际采样间隔与许可，并维护快照/回放链路。
- 模型研究需要冻结评测协议、补齐强基线和残差分析，再决定适配器、慢模型和动作条件模型的训练规模。
- 系统工程需要提供目标负载、时限预算、可用硬件和受控接口，验证并发读写、超时与回退。
- 无线业务侧需要明确允许动作、硬约束、效用目标与可接受误差，提供实际生效配置及时间对齐的遥测。

每一阶段先以有限样本和小规模资源验证，再根据证据扩大；模型、数据和预算变化需要形成新的可追溯实验版本。

## 6. 本阶段工作的价值与当前边界

**数据工程价值：**统一不同速率、不同年龄和不同来源的数据，降低错配、未来信息泄漏与重复取数风险，使预测输入能够复核。该工作同时支撑轻量模型和未来多模态模型，具有较强复用性。

**模型研究价值：**将“慢层是否必要”转成有基线、有消融、有资源成本的实验问题。真实数据结果已经提示指标选择与持久性基线的重要性，便于把训练资源集中在确有提升空间的任务。

**系统价值：**把任务管理、物理预测、策略评分和安全执行分开，支持替换模型、追踪实际动作及定义失败行为；多时间尺度缓存和快照为该系统提供共同数据基础。

**研究与标准化价值：**已形成 Agentic RAN 架构、多时间尺度处理、上下文适用条件和反馈语义的材料，可支持后续接口分析、可复现实验与提案研究。当前材料属于研究设计，未证明标准采纳、跨厂商互通、专利新颖性或标准必要性。

当前最值得投入的工作，是把数据结构与因果时间链路做成可运行模块，并用完整真实数据基线验证预测能力，再判断慢模型和智能体组合能带来多大增益。
