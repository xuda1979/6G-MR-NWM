# 基站规划器动作设计

更新日期：2026-10-29。项目：`xuda1979/6G-MR-NWM`。

本文独立说明规划器需要规划什么、由谁执行、需要哪些输入与反馈，以及如何验证。公开数据的原始文件核查、字段哈希和仿真数据方案另见[动作数据核查与训练方案](PLANNER_ACTIONS_AND_DATA_CN.md)；整体进度见[基站世界模型进展报告](PROGRESS_REPORT_CN_2026-10-23.md)。除双链路功率候选审计外，下述闭环均属设计与研究计划。

## 1. 规划器具体负责什么

| 组件 | 输入与输出 | 责任 |
|---|---|---|
| 上层智能体/任务管理 | 业务要求、告警、能力目录 → 结构化目标、约束、任务与重规划请求 | 确定任务、调用已声明的能力；不直接生成自由文本射频命令 |
| 世界模型 | 决策时可见历史、候选动作、外生条件 → 后续状态及业务反馈预测 | 回答“执行这个动作之后会怎样”；预测不等于已发生的测量 |
| 规划器 | 同初态下的候选预测、业务目标、约束和计算预算 → 选中的动作/动作序列 | 回答“应该选哪个”；可先采用枚举、采样或模型预测控制（MPC），不必先训练策略网络 |
| 策略网络（可选） | 历史、目标和能力范围 → 动作建议 | 在搜索成本过高时，可模仿经验证的规划决策或通过强化学习训练；当前未实现 |
| 约束检查与执行器 | 动作请求 → 接受、裁剪、拒绝、实际生效动作及时间 | 检查可直接验证的动作限制，调用设备/模拟器接口并确认结果；模型评分不能代替执行确认 |

目标权重用于动作评价，不直接进入固定动作下的物理转移。吞吐、时延和能耗是结果/目标，不是可直接下发的动作；自然业务到达、自然 UE 运动和信道变化通常属于外生条件。

## 2. 六类动作及其规划内容

| 动作族 | 规划器选择什么 | 必需状态与反馈 | 主要约束 | 本项目阶段 |
|---|---|---|---|---|
| **A1 功率/干扰** | 链路发射功率、功率上限/包络；接口支持时协调相邻小区 | 实际功率、信道/干扰、负载/队列；后续吞吐和干扰 | 总/单链路功率、功率变化率、邻区限制；保持动作与失败回退 | 当前只有两链路归一化功率的合成参考 |
| **A2 资源/调度** | 切片 PRB/RBG 预算、RR/PF/WF 等可用模式；本地控制器再做 UE 级分配 | 队列、业务需求、CQI、实际预算及授予资源、吞吐和业务时延 | 资源守恒、整数/粒度、最低保障；资源单位和控制权一致 | 建议首个新增网络动作任务，优先利用公开 RF 配置实验 |
| **A3 波束管理** | 波束索引、候选波束集合、扫描/重测时机 | 感知/位置历史、已知波束测量、遮挡；实际切换/探测反馈 | 码本合法性、扫描/切换成本、可用信息时刻 | 先做真实配对数据的独立选择/排序；多步控制另验收 |
| **A4 移动性/关联** | 目标小区、是否触发切换、接口开放的触发参数 | 服务/邻区质量、移动历史、当前关联、实际切换事件与后果 | 目标可达、驻留/滞回、中断成本、避免频繁往返 | 后续扩展；位置轨迹不能代替实际切换日志 |
| **A5 准入/节能** | 业务接纳/延后、小区或载波休眠/唤醒 | 需求、覆盖、邻区能力、设备状态及能耗/业务后果 | 服务承诺、覆盖、容量、唤醒时延；设备总能耗需独立测量或标定 | 后续扩展；不能把归一化功率代理指标当作实测总能耗 |
| **A6 测量/上报** | 测量周期、上报频率、启用传感器、重新测量 | 数据年龄/质量、采集与通信开销、后续可见信息 | 最大过期时间、测量预算、必须保留的反馈 | 后续扩展；需要建模观测过程，离线删样本不等于真实测量控制 |

上表是可研究的动作分类，不代表当前执行接口已支持全部动作。调制编码、HARQ 等具体底层参数是否列为独立动作，取决于执行器是否开放控制、是否有匹配数据以及研究问题是否需要；不能仅因某个 KPI 列存在，就认定它是可控动作。

计算卸载、端边推理和缓存可作为后续跨域动作，但需要增加计算/存储状态、执行器、成本与反馈，不计入当前论文已验证的 RAN 动作空间。模型选择、上下文刷新和请求重规划属于上层管理操作，应与 A1–A6 的网络执行动作分别记录。

## 3. 多时间尺度怎样分工

| 层次 | 选择内容 | 与下一层的关系 |
|---|---|---|
| 较慢监督 | 业务目标、允许能力、约束，跨小区任务与较慢配置 | 给出可验证任务与动作权限；目标变化可能只需重新评分 |
| 资源/模式规划 | 一段有效期内的切片预算、调度模式、功率包络 | 定义本地控制器的可行域，明确生效时间、持有时间和撤销方式 |
| 本地快速执行 | 在当前预算、模式和包络内落实资源与链路控制 | 返回实际生效值与后续遥测；快速执行不必每次调用大语言模型 |

分层描述控制所有权与依赖，不是统一标准时限或实测性能承诺。模型的 K 步也不自动等于若干无线时隙。动作有效期必须采用实际物理时间，逐时隙 MAC 调度不能仅因存在 Near-RT RIC 就交给远端慢模型。

**同一执行器、同一控制区间只允许一个有效控制者。** 慢层更换预算/模式时，应指定版本和切换点；本地控制不能与另一个智能体同时写同一资源。动作切换成本、执行延迟与上下文失效需要进入评价或拒绝条件，不能把配置变更视为零成本瞬时事件。

## 4. 首期任务与当前实现

建议分成三项独立验收任务：

1. **功率合成参考。** 保留双链路环境，检查动作敏感性、偏好隔离和有限候选 regret，作为模型与接口回归依据。
2. **切片预算＋调度模式。** 先审查公开 RF 实验中的实际配置与反馈，在核验覆盖的动作域内做条件预测/候选比较；缺少切换覆盖时用明确标记的可控仿真补齐，不先加入全部动作族。
3. **配对感知波束选择。** 单独利用真实感知与波束测量评估选择/排序；扫描得到的最优标签不等于已执行策略，长期收益另设实验。

现有 `src/mr_nwm/planning.py` 的 `planning_audit` 仅枚举两路功率等级 `{0.1, 0.4, 0.7}` 的组合，按总功率预算过滤。候选在模型调用中重复到预测时域，但只用第一步预测计算效用；它没有搜索一般动作序列、训练 actor 或接入真实执行器。极小功率预算下的零功率候选只是该合成审计的可行动作，不能推广为任意基站业务的安全回退。

UC6/UCC 的结果来自两组独立 LSTM；没有在这些数据上训练或评测语言慢层＋快层的完整动作条件模型。新增动作定义不改变这一实验边界。

## 5. 一次规划到执行的完整流程

1. **固定输入。** 在决策时刻冻结可用观测快照，记录年龄、缺失、外生条件、模型/上下文及策略版本；事后到达的 KPI 不进入本次输入。
2. **确认能力。** 读取执行接口支持的动作、对象、单位、上下限、资源粒度与控制权；屏蔽不支持或超出已验证覆盖的候选。
3. **生成候选。** 在约束及计算预算内建立候选动作/序列，包含已验证的保持/回退方案；不要把无动作数据中的缺失填成零功率。
4. **隔离推演。** 各候选从同一初态、同一上下文和各自独立递归记忆开始；一个候选的末态不能成为另一个候选的初态。
5. **评价与检查。** 按冻结目标累计效用，加入切换/测量等成本；先检查可直接验证的动作约束。预测的业务约束满足情况需保留不确定性及适用范围，不是形式保证。
6. **提交与确认。** 滚动规划原则上先提交第一步，记录请求、接受/裁剪/拒绝和实际生效时间；未确认请求不能视为已执行事实。
7. **独立反馈与重规划。** 收集生效后的测量，计算预测残差和业务结果；遇到观测过期、模型超域、执行失败或目标变化，按明确规则保持、回退、刷新或重新规划。

例如，在“保障低时延业务并提升吞吐”的任务中，规划器可以比较几组切片预算与调度模式，用世界模型预测各组后续队列和吞吐，剔除资源不合法方案后评分，再执行第一步并等待反馈。该例说明工作流程，尚无本项目闭环收益结果；不能用它替代具体数据或实验。

## 6. 动作记录与验收要求

| 记录组 | 最小内容 |
|---|---|
| 作用范围 | episode、基站/小区/切片/UE、能力与动作 schema 版本 |
| 决策依据 | snapshot、决策时间、模型/ContextID/PolicyID、可见观测与候选集 |
| 动作定义 | 动作族、参数、单位、上下限/粒度、有效期和持有时间 |
| 执行过程 | request ID、请求值、实际生效值、生效时间、状态/拒绝原因、执行器版本 |
| 后续证据 | 对齐测量、缺失/质量、目标及成本公式、预测残差、约束结果、回退/重规划原因 |

这些是接口设计要求，当前尚不是已实现的通用动作 schema。资源需求、窗口内授予资源统计和窗口开始前选择的预算含义不同；应分别记录，不能混用。

验收应同时覆盖预测、选择和执行：

- **预测：**一步/多步误差、动作效果误差，按场景和动作覆盖分层报告。
- **选择：**同一候选集、约束和计算预算下的排序 regret；不使用动作的预测器和规则/适用优化器作为对照。
- **闭环：**长期效用、真实业务违约、尾时延/丢包、动作切换与测量成本；预测得准不能代替控制收益。
- **工程：**采集至确认的端到端延迟、截止违约、过期/超域拒绝、候选状态隔离、幂等和失败恢复。
- **泛化：**完整场景/episode 与共享分支原点分组隔离；仿真、RF 实验和独立实网分别计证。

普通离线日志不能自动提供反事实最优动作或可信长期策略收益；只有可取得相应反事实的受控环境才能直接计算该类 oracle。约束过滤只保证已直接检查的动作限制，不构成完整无线可靠性证明。

## 7. 与数据方案和论文的关系

动作条件世界模型先学习后果，搜索规划器再利用后果选择，只有搜索成本需要时才训练 actor。公开数据的动作字段、来源等级、抽检覆盖和模拟数据产生步骤集中在[数据核查文档](PLANNER_ACTIONS_AND_DATA_CN.md)，避免与本动作设计重复维护。

论文动作定义见 `paper/planning_actions.tex`。本文件与论文、基站进展报告共同维护；代码、真实数据验证或允许动作发生变化时，更新对应实现证据，不能只扩写动作列表。
