# 规划器动作定义、公开动作数据核查与训练方案

核查日期：2026-10-29。对应论文新增的动作定义、动作表与数据小节。本文区分当前实现、数据核查及后续方案；没有新增训练成绩或实网控制结论。

**公开动作相关数据确实存在，但覆盖范围有限。** UC6/UCC 的现有观测预测不能训练完整规划器；DeepSense 能监督波束选择；Colosseum 数据为资源配置与调度模式提供动作相关监督。对于尚无受控测量覆盖的多步动作及切换后果，建议另建可控仿真轨迹，并保留独立实测验收。不能概括为“公开数据都没有动作，所以只能模拟”。

## 1. 世界模型、规划器与策略网络

| 对象 | 回答的问题 | 训练/实现方式 | 当前仓库状态 |
|---|---|---|---|
| 动作条件世界模型 | 执行这个动作，接下来会怎样？ | 可见历史、实际生效动作、外生条件及后续状态监督；部分可观测任务需历史记忆 | 双链路合成参考已有动作条件预测；UC6/UCC 独立 LSTM 只做无动作观测预测 |
| 规划器 | 比较未来后果后，应该选择什么动作或序列？ | 枚举、采样搜索或模型预测控制（MPC）；**不必先训练策略网络** | `src/mr_nwm/planning.py` 只有有限功率候选的单步评分审计 |
| 策略网络/actor | 能否直接输出好动作，减少搜索成本？ | 可模仿经验证的规划决策，或通过强化学习优化长期目标 | 尚未实现/验证；历史行为动作不自动等于最优动作标签 |

建议论文称为“动作条件世界模型＋约束规划器”；新增直接输出动作的网络时再称其为“策略网络”，避免将三者统称“动作模型”。

规划器在约束内比较有限时域的候选序列，累计吞吐、排队/业务时延、能耗及切换成本等效用；先执行第一步，再依据新观测重规划。目标权重和约束由任务配置给定，**不需要公开数据提供偏好标签**；真实时延/能耗收益则需要可核验反馈。

当前 `planning_audit` 枚举两链路功率等级 `{0.1, 0.4, 0.7}` 的组合，按总功率上限筛选；模型调用中重复候选，但只用第一步预测评分。它没有搜索一般动作序列，没有训练 actor，也不等于已经跑通长期闭环 MPC。吞吐和能量均为该合成环境的代理指标。

## 2. 应规划的动作与优先级

| 动作族 | 具体决策与时间分工 | 必需反馈与约束 | 研究范围 |
|---|---|---|---|
| 功率/干扰 | 上层定功率上限/包络，本地较快调整发射功率 | 实际功率、信道/干扰、负载；总功率、变化速率、邻区干扰上限 | **保留当前双链路合成回归任务**；有变化的功率日志尚未确认 |
| 资源/调度 | 上层选择切片 PRB/RBG 预算及 RR/PF/WF 等模式；本地做逐时隙 UE 分配 | 队列、到达业务、CQI、实际资源及吞吐；资源守恒、整数粒度、最低保障、单一控制权 | **建议首个新增动作任务**，与已发现的公开配置数据最匹配 |
| 波束管理 | 波束索引、候选集合、扫描/重测触发 | 测得功率、遮挡/运动、切换/探测后果；码本、扫描与切换开销 | 可先单独做真实测量监督的选择/排序；长期闭环另验收 |
| 移动性/接入 | 关联小区、切换目标、触发条件或参数，事件驱动 | 服务/邻区质量、实际切换和后果；驻留、滞回、可达目标、中断成本 | 后续扩展；位置轨迹不能替代实际切换记录 |
| 准入/节能 | 接纳/延后业务，载波/小区休眠与唤醒，随负载较慢调整 | 需求、覆盖与能耗；业务承诺、唤醒时延 | 后续扩展；发射功率不能直接代替设备总能耗 |
| 测量/上报 | 测量周期、上报速率、启用传感器或重新测量 | 观测年龄、质量和采集成本；最大过期时间、采集预算 | 改变可见信息，需要建模观测过程；离线删数据不等于执行真实测量动作 |

这里的时间层次是设计分工，不是各动作的统一标准时限或本项目实测时限。Near-RT RIC 和 E2 节点内部控制需按所用接口/场景确定，见论文 ETSI/O-RAN 引用；大语言模型不直接承担逐时隙 MAC 调度。

吞吐、时延、能耗是结果/目标；自然业务到达、UE 运动和信道一般是外生条件；权重是策略配置。刷新上下文、选择预测模型和请求重规划属于上层操作。卸载与缓存需要独立计算/存储状态和执行器，暂不计入本文已验证动作。

**当前建议收敛为两条有界研究线：**继续用双链路功率验证动力学与偏好隔离，新增“切片预算＋调度模式”任务；波束选择作独立真实配对多模态任务。不把全部动作组合成没有覆盖证据的大动作空间。每种动作需要 capability mask、单位、合法域、粒度、持有时间、执行确认及保持/回退方案；零功率不是所有业务的安全回退。

## 3. 公开数据能提供什么动作监督

| 数据源与官方入口 | 动作相关信息 | 可训练内容与边界；核查状态 |
|---|---|---|
| [UC6](https://zenodo.org/records/10037164)、[UCC production](https://github.com/uccmisl/5Gdataset) | 本仓库已核验字段不含实际功率、PRB、波束控制及生效日志 | 保留真实观测预测/表征任务；未知动作不可补零。独立 LSTM 成绩不属于语言慢层＋快层动作训练 |
| [DeepSense 位置辅助波束任务](https://www.deepsense6g.net/position-aided-beam-prediction/)／[LiDAR 任务](https://www.deepsense6g.net/lidar-aided-beam-prediction/) | 官方提供 64 维扫描接收功率向量、由向量导出的最优波束索引，依具体场景/任务核对 | 可以训练选择/排序和相对测得最优功率的损失；最优标签不等于已执行策略轨迹，不提供完整队列与切换代价。此次核对官方任务说明，未新增训练 |
| [Colosseum COMMAG](https://github.com/wineslab/colosseum-oran-commag-dataset) | README 描述调度、RBG 分配与动态调整；实际抽检 UE CSV 有 `slice_prb`、`scheduling_policy`、`power_multiplier` 及 KPI | RF 仿真实验平台数据；可审查资源/调度配置条件学习。**单份抽检文件配置恒定**，README 调整方案不能替代该文件的实际变化。各下载一份完整 UE 文件，未训练 |
| [Colosseum ColO-RAN](https://github.com/wineslab/colosseum-oran-coloran-dataset) | README 列 RR/WF/PF 及资源配置；实际 CSV 有同类配置、队列、CQI、吞吐及资源统计 | 同属 RF 仿真实验平台；跨配置覆盖、单位与时钟需核验。单文件恒定配置不能监督切换瞬态。各下载一份完整 UE 文件，未训练 |
| [Commercial Traffic Twinning](https://openrangym.com/datasets/open-ran-commercial-traffic-twinning-dataset)／[官方仓库](https://github.com/wineslab/open-ran-commercial-traffic-twinning-dataset)／[原论文](https://arxiv.org/abs/2409.16217) | 一基站、八 UE；5 种切片资源配置、RR/PF 两种调度、3 类业务回放，共 30 组配置；PHY/MAC/App 反馈与日志 | 适合优先审查切片/调度任务。商用来源是业务轨迹，动作后果产生于 Colosseum。MAC 统计按 250 ms 汇总，不能还原逐时隙动作。此次只查官方说明和论文，未下载完整归档或训练 |

波束选择已有真实测量监督，不必等待仿真；受限资源配置比较已有可审查的 RF 实验数据；覆盖功率、调度、切换、节能的多步规划，本次未找到可以直接使用的完整统一数据集。这是对已核查来源的判断，不是对所有公开数据的不存在性证明。

### 3.1 两份完整 CSV 的抽检记录

两个文件均有 `Timestamp`、`slice_id`、`slice_prb`、`power_multiplier`、`scheduling_policy`、`dl_buffer [bytes]`、`tx_brate downlink [Mbps]`、`dl_cqi`、`sum_requested_prbs`、`sum_granted_prbs` 等字段。

|---|---|---|
| 固定版本 | `7331cd725fe42b5b9930fdc8acee3006cea00bd7` | `bd86629d07d5fbfb778ebe3afd9d0b05e5191c6b` |
| 仓库内路径 | `slice_mixed/rome_slow_close/tr0/exp1/bs1/slices_bs1/1010123456002_metrics.csv` | `rome_static_medium/sched0/tr0/exp1/bs1/slices_bs1/1010123456002_metrics.csv` |
| 字节／数据行（不含表头） | 203,379／1,801 | 248,373／2,090 |
| SHA-256 | `1dbe4497b42cf3aa1a9d7b2279993837d5d532a8b7e3de1ee454d2bef134040d` | `fc35e1fb612fbf1361a76e4c4c1e4d43414da878de9568741e442494ef5606ab` |
| 配置唯一值 | `slice_id=1; slice_prb=4; power_multiplier=1; scheduling_policy=0` | `slice_id=2; slice_prb=5; power_multiplier=1; scheduling_policy=0` |
| 相邻时间戳主要差值 | 250（1,766 次），还有 249/251 等 | 250（1,167 次），249（458 次），251（456 次） |

抽检限制和接入要求：

1. 两文件 `power_multiplier` 始终为 1，不能据此宣称已有功率干预覆盖；全库功率变化尚未确认。资源和调度也恒定，不能当作切换轨迹。
2. COMMAG README 有动态调整表，但这份实际文件没有相应变化，必须逐轨迹核验；有动作列和有动作变化是两件事。
3. `slice_prb` 字段、README 中 RBG/PRB 单位与带宽配置需逐包映射；不同带宽的 RBG 不能直接当作同样数量的 PRB。
4. `sum_requested_prbs` 是需求，`sum_granted_prbs` 是窗口内授予资源的总量，不自动等于窗口开始时上层选择的预算，也不自动提供无混杂的动作因果效应。
5. 明确时间戳所指区间、配置生效点、UE/切片/基站对齐；窗口结束才知道的吞吐不能作为该窗口开始时的输入。恒定动作轨迹可学配置内响应，但不能单独识别切换瞬态。

两个源码仓库 LICENSE 均为 GPL-3.0；本仓库不再分发原始 CSV。Twinning 说明仓库标注 CC-BY-SA-4.0，完整数据归档的具体条款仍需按下载对象复核；DeepSense 按场景/任务条款使用。“公开可见”不自动等于所有用途均可使用。

## 4. 模拟数据的必要性与产生方式

**缺少受控动作覆盖的多步规划建议补仿真，已有实测监督的任务不必一律依赖仿真。** 原有真实数据实验继续保留；新仿真用于动作后果、动作切换和故障恢复，单独计证。这是后续方案，本次没有新增模拟器或运行仿真训练。

优先选有资源、队列、业务及干扰反馈的包级环境，例如 [ns-3/5G-LENA](https://5g-lena.cttc.es/features/)，冻结版本并实现选定动作的控制/日志接口。其功能页区分已支持、部分支持与路线图项目，不能假设任意切片、E2 或波束管理均已完整可用。射线追踪/传播信道本身不能生成完整调度排队闭环。

### 4.1 每个 episode 的最小记录

| 信息 | 必需内容 |
|---|---|
| 场景/来源 | episode、分支原点、实体/拓扑、单位/频段、模拟器版本、参数、随机种子；逐字段区分 field、RF-emulator、simulated、derived |
| 当时可见观测 | 历史、事件时间、可用时间、年龄、质量/缺失、外生业务与移动条件 |
| 动作与执行 | 可行动作域、请求动作、实际生效值、生效时间、持有时间、接受/裁剪/拒绝/超时、保持/回退 |
| 后续反馈/成本 | 吞吐、队列、业务时延/丢包、实际资源，任务所需的能耗/切换/测量成本；按冻结公式从反馈计算奖励 |
| 行为与版本 | 行为策略、探索方式、已知时保存动作概率，模型/策略/预处理版本，约束及训练/验证/测试分组 |

训练转移使用“可见历史＋实际动作→后续状态”。未执行的候选不算实际动作；不同城市、运营商或日期的数据不拼成同一 episode 的伪同步轨迹。

### 4.2 收集、训练与验收顺序

1. **真实数据先训练表示/观测任务。** 修复因果预处理并保留强基线。DeepSense 的同帧完整扫描功率作标签/评价，不能泄漏进扫描前决策的输入。
2. **收集有变化的可行动作。** 组合规则、受约束探索与优化策略，不只保留“专家偏好动作”；覆盖负载突变、邻区干扰和执行延迟等已选场景。
3. **仿真状态分叉。** 同初态执行多个候选，匹配业务、移动和信道外生随机过程，计算动作差异；若随机数消费依赖动作，需要独立管理外生随机流，仅相同 seed 不保证外生过程相同。
4. **先学动力学，再接搜索。** 报一步/多步误差与动作效果误差；候选记忆分别初始化。在固定约束/计算预算下对比规则/优化控制、无动作预测器及单尺度模型。
5. **必要时才蒸馏 actor。** 搜索过慢时，模仿已验证规划决策或做受约束 RL，再比较与原搜索器的收益、延迟和约束违反。
6. **独立验收。** 报候选排序 regret、长期效用、服务违约、尾时延/丢包、切换/测量成本与端到端耗时；仿真、RF 实验、实网分开报告。只有取得反事实的仿真可直接计算相应 oracle，普通离线日志不自动提供可信闭环收益。

划分按场景/完整 episode/共享分支原点分组；同初态不同分叉不能跨训练测试。同一业务回放的多个配置要整体分组，另设独立负载与配置外推任务。真实数据可校准仿真，但独立实测验收集不参与校准。LLM 可设计场景和约束，**物理后果必须由模拟器或仪器计算，不能由 LLM 编写或由被测模型自证**。

## 5. 已完成与未完成

论文已补动作分类、层次分工、规划公式、公开数据核查与补齐方案；动作表扩展项仍是研究定义。当前动作条件成绩仍来自双链路合成参考，UC6/UCC 仍为独立 LSTM。Colosseum/Twinning/DeepSense 本次均未计作已完成训练，没有新增真实功率优化、长期闭环或多动作联合控制成绩。
