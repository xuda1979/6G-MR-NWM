# 有界规划器：实现、运行与验证

更新日期：2026-10-29。对应[动作设计](PLANNER_ACTIONS_CN.md)的首个代码版本。当前提供离线规划、两切片合成队列闭环、实际动作转移记录和现有世界模型接口，不包含真实设备控制。

## 1. 已实现的最小闭环

| 文件 | 已实现内容 |
|---|---|
| `src/mr_nwm/action_space.py` | 不可变动作名称/单位/上下界；整数资源、总预算、变化率、能力启用与有限数值检查 |
| `src/mr_nwm/control_planner.py` | 多步有限候选搜索；候选屏蔽、折扣、动作切换成本、状态约束回调、搜索与耗时预算、无可行方案及独立候选状态 |
| `src/mr_nwm/slicing.py` | 两切片、每片两个 UE 的确定性流体队列；预算、轮询与比例公平评分；业务到达、服务与队列反馈 |
| `src/mr_nwm/control_records.py` | 请求和实际动作分离；确认生效时间与持有期；因果观测窗口、来源、场景分组、JSONL 校验与读回 |
| `src/mr_nwm/planning_adapters.py` | 归一化功率能力及现有 MR-NWM `rollout` 的单样本规划接口；按宏窗口补齐动作，推理后恢复模块模式 |
| `scripts/planner_demo.py` | 单步/多步闭环、覆盖全部可行候选的采集 episode、已提交功率检查点接入检查和来源清单 |

原 `planning_audit`、模型、数据生成器、目标和论文实验数字保持原测量契约。新增规划器采用单独接口与结果目录；没有将原单步分数改名为多步成绩。

## 2. 运行与输出

在已安装项目依赖的环境运行：

```bash
make planner-smoke
python scripts/planner_demo.py --output runs/my-planner-check --steps 8 --seed 11
```

第一个命令使用固定演示目录并显式允许覆盖；第二个命令默认拒绝覆盖已有结果。CI 在 Python 3.10/3.12 的原检查之外运行 `planner-smoke`。

输出包含：

- `summary.json`：动作规格、场景、初态、解析后的规划配置、效用定义、模拟器版本、来源文件 SHA-256、检查点 SHA-256、运行版本及各策略记录。
- `transitions.jsonl`：确认生效的状态—动作—后续状态转移。导出后立即读回并核对；不把未确认的请求填成零动作。

可直接调用规划器：

```python
from mr_nwm.control_planner import BoundedPlanner, PlannerConfig
from mr_nwm.slicing import SliceState, TwoSliceQueueEnvironment, slice_utility

env = TwoSliceQueueEnvironment()
state = SliceState((3, 3, 3, 3))
planner = BoundedPlanner(env.spec, PlannerConfig(horizon=2, max_sequences=512))
plan = planner.plan(state, env.candidates(), env.rollout, slice_utility)
if plan.first_action is not None:
    observed_next = env.step(state, plan.first_action)  # 仅执行合成环境一步
```

## 3. 动作、预算和失败语义

资源动作是四元组：`(切片0预算, 切片1预算, 切片0模式, 切片1模式)`，模式 0 为轮询，1 为速率/历史吞吐比例公平评分。预算为抽象资源块，负载为抽象数据量；这里没有标定的 PRB、无线波形、包级时延或 3GPP 一致性。不能将模式 1 的此实现视为任意设备 PF 调度器的等价副本。

功率规格约束归一化坐标、总功率和可选变化率。变化率配置存在时，必须提供实际前一动作。只有所提供预测器及适配器支持的变量才有执行语义；为其他动作族编一个名称不等于已有设备能力。

`considered` 包括因变化率等原因被拒绝的完整序列，`evaluated` 是预测器调用次数，`max_sequences` 限制前者，避免全不可行时反而无限搜索。输入候选数量与动作向量读取也有界。结果中的 `truncated=true` 表示只搜索了有序候选空间的一部分，不能称为全局最优。候选顺序影响截断搜索的覆盖；接口不宣称自动发现最优候选。

每次预测独立复制初态，逐步复制生成器产生的状态，避免重用可变缓冲区覆盖早期预测。外部预测器不能在隐藏的全局变量中跨候选保留记忆；已有模型适配器每次重新开始 `rollout`，并恢复原有 train/eval 模式。该模式切换接口不支持多个线程同时共享同一可变模型实例。

无可行动作、无满足状态约束的序列或超时，返回 `no_plan` 且没有首动作；不自动发出零功率。非有限/错误维度的动作不能入选，畸形预测或非有限评分会报错。同步回调不能被抢占；耗时预算只会在回调返回后拒绝过期结果，不能据此声称硬实时截止保证。状态约束回调检查的是预测状态，不保证未来实测状态一定满足业务约束。

## 4. 可用于训练的记录与来源

转移必须具备已确认的实际动作、生效时间和正持有期；历史观测在请求前已可用，后续观测在动作生效后、确认持有期内。拒绝/超时请求可以作为执行反馈对象保存，但不能构造动作条件训练转移。请求被裁剪时，训练标签使用实际值。

同一场景的单步、多步和覆盖采集 episode 使用同一 `group_id`，训练/测试不能把它们视为独立场景。覆盖 episode 遍历本环境全部 20 种满预算候选，以免只保存某一控制策略偏好的动作。该覆盖不等于真实无线空间、多场景或所有动作序列已经覆盖。

数据读取检查 schema、动作规格名称、实际动作可行性、重复请求、数值与因果时间。完整动作约束、场景、单位及源代码哈希在配套摘要中保存；单独复制 JSONL 时必须同时保留这些信息。来源字段是生产者声明，不能替代真实数据获取与认证。该版本生成的来源明确为 `simulated`，没有将公开真实数据补出未知动作。

## 5. 验证与结果边界

当前本地 CPU 检查：181 项测试通过，1 项因未下载 UCC 原始数据而跳过；原 24 组确定性检查点评估与原始指标一致。新增测试覆盖手算的多步选择、折扣和切换成本、预算/整数/变化率/屏蔽、搜索上限、超时、状态隔离、生成器缓冲区重用、反馈与数据篡改、真实模型调用及导出读回。

独立复核另算了 50 个三步规划案例，并从导出的实际动作、队列和服务量重算效用与守恒关系。复核发现并修复了可变预测生成器的状态别名问题；没有通过放宽测试来掩盖差异。

`make planner-smoke` 的固定种子 11、四步演示导出 28 条转移：单步与多步各 4 条，覆盖采集 20 条。默认两步规划每次枚举 400 个资源/模式序列；已有 `full_11.pt` 接口检查枚举 36 个功率序列。对应摘要和记录见[演示目录](../results/planner_smoke/summary.json)。

这个短程例中，单步累计效用约 5.3066，多步约 4.9890；独立复核的另一场景也出现多步较差。较长局部预测时域不保证有限采样下长期收益更好，不能把管线可运行表述为 MPC 优势。

切片推演直接调用已知合成转移，不是训练后的切片世界模型；功率检查使用已有合成任务检查点，只验证接口。尚未训练切片动力学或 actor，尚未验证实网、RF 实验迁移、RIC/E2 执行、Ascend/NPU 或确定性控制时限。后续先做独立场景及动作覆盖，再训练切片动力学，最后验证规划收益与迁移。
